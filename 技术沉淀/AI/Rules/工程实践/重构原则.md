# 重构原则

1. **保持公共 API 不变**
   保持公共方法名称、签名和返回值不变，除非绝对必要。

2. **提取为私有方法**
   将公共或重复代码移入私有方法或辅助方法，消除重复。

3. **提升可读性、可维护性和效率**
   重构代码以提高清晰度、便于修改，并在可能的情况下提升性能。

4. **利用现代语言特性**
   使用现代语法或语言特性（如 lambda、流、模式匹配）简化代码。

5. **重命名变量并重新组织代码**
   为清晰起见重命名变量，并根据需要调整代码顺序以改善逻辑流。

6. **删除死代码或未使用代码**
   删除不必要、未使用或注释掉的代码，保持代码库整洁。

7. **遵循一致的编码规范**
   遵守项目风格指南，包括缩进、命名和空格。

8. **添加适当的文档**
   在逻辑复杂或不明显的地方更新或添加注释和文档。

9. **编写或更新单元测试**
   确保现有测试仍然通过，必要时添加测试以覆盖新增或变更的逻辑。

10. **限制变更范围**
    进行小型、增量式的改动，以最小化风险并便于代码审查。

11. **避免更改业务逻辑**
    除非明确要求，否则不要更改业务规则或引入新功能。

12. **确保向后兼容性**
    保证代码与现有客户端/用户兼容，除非允许破坏性变更。

13. **提供完整、无省略的代码**
    **重构回复中始终提供完整、无省略的代码。** 避免使用省略号（…）或遗漏部分内容，以确保完整性、上下文和可审查性。
