# 单元测试开发规范

## 测试环境配置

### 基础环境

- **测试框架**: pytest（支持异步测试、参数化测试、fixture 等）
- **Python 版本**: Python 3.11+
- **依赖管理**: uv（用于快速安装和管理 Python 包）
- **Mock 库**: unittest.mock（标准库，用于模拟依赖对象）

---

## 核心测试要求

### 1. 测试优先级策略

#### 1.1 Happy Path 优先

- **首要任务**: 始终优先生成 Happy Path 测试用例
- **定义**: 覆盖正常业务流程，输入有效参数，预期正常输出

#### 1.2 边界条件测试

- **空值处理**: `None`、空字符串、空列表等
- **边界值**: 最大值、最小值、临界点
- **异常情况**: 无效输入、权限不足、资源不存在

#### 1.3 异常场景测试

- **业务异常**: 用户已存在、权限不足、数据冲突
- **系统异常**: 网络错误、数据库连接失败、超时
- **输入验证**: 格式错误、类型错误、范围超限

---

### 2. 测试结构规范

#### 2.1 AAA 模式（Arrange-Act-Assert）

```python
@pytest.mark.asyncio  # 异步测试装饰器
async def test_method_name_scenario():
    """清晰描述测试场景的 docstring"""
    # Arrange - 准备测试数据和模拟对象
    mock_dependency = Mock(spec=DependencyClass)
    test_data = TestDataModel(...)

    # Act - 执行被测试的方法
    result = await service.method_under_test(test_data)

    # Assert - 验证结果和行为
    assert result.expected_field == expected_value
    mock_dependency.method.assert_called_once_with(expected_args)
```

#### 2.2 测试命名规范

- **格式**: `test_{方法名}_{场景描述}`
- **示例**:
  - `test_create_user_success()` — 成功创建用户
  - `test_create_user_duplicate_username()` — 用户名重复
  - `test_create_user_invalid_email()` — 邮箱格式无效

---

### 3. 断言质量要求

- **每个测试必须至少包含一个有效断言**
- **断言失败必须能明确指示测试失败原因**
- **避免无意义的断言**（如 `assert True`）

**异常断言**：
```python
with pytest.raises(ValueError) as exc_info:
    service.method_with_invalid_input(bad_data)
assert "specific error message" in str(exc_info.value)
```

---

### 4. Mock 和依赖处理

- **外部依赖必须 Mock**: 数据库、网络请求、文件系统、第三方服务
- **内部纯函数可以不 Mock**: 数据转换、计算逻辑
- **使用 `spec` 参数确保类型安全**: `Mock(spec=TargetClass)`

```python
# 正确的 Mock 配置
mock_repository = Mock(spec=UserRepository)
mock_repository.find_by_username = AsyncMock(return_value=None)
mock_repository.create = AsyncMock(return_value=expected_user)
```

---

### 5. 异步测试处理

```python
@pytest.mark.asyncio  # 必须添加此装饰器
async def test_async_method():
    result = await async_service.method()
    assert result is not None
```

```python
# 异步方法必须使用 AsyncMock
mock_repository.async_method = AsyncMock(return_value=expected_result)
```

---

### 6. 测试独立性要求

- **每个测试必须独立运行**，不依赖其他测试的状态
- **不能有测试执行顺序依赖**
- **使用 Mock 避免外部依赖**

### 7. 错误处理和稳定性

- **测试结果必须可重复**: 多次运行应产生相同结果
- **避免随机性**: 不使用随机数据，使用固定的测试数据
- **时间处理**: 对时间相关测试使用 Mock 或固定时间戳

---

## 测试生成检查清单

### 基础检查
- 测试方法命名遵循 `test_{method}_{scenario}` 格式
- 包含清晰的测试文档字符串
- 遵循 AAA 模式结构
- 至少包含一个有效断言

### 异步测试检查
- 异步方法添加 `@pytest.mark.asyncio` 装饰器
- 使用 `AsyncMock` 模拟异步依赖
- 正确使用 `await` 关键字

### Mock 检查
- 外部依赖使用 Mock 对象
- Mock 配置包含 `spec` 参数
- 验证 Mock 方法的调用情况

### 覆盖性检查
- 优先实现 Happy Path 测试
- 包含主要的边界条件测试
- 覆盖预期的异常场景
